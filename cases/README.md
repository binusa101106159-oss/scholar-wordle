# 個案追蹤

七欄：姓名、病歷號、日期、目的、診斷、回診時間、備註。
新增／編輯需按儲存，刪除需確認。病歷號以字串保留開頭的0；日期預設當天，回診時間為自由文字。桌機表格、手機卡片，搜尋涵蓋七欄。

Google登入後，以ScholarSync與Firestore儲存，每位病人為獨立且具revision的項目。只有已驗證的擁有者帳號可讀寫自己的資料。清單格式仍為version:1及records陣列，另有createdAt供排序。
資料只暫存在頁面記憶體，不寫入localStorage、公開GitHub或service-worker快取。未登入不能新增；儲存／刪除等待伺服器確認後才關閉視窗。

表單保留開啟時的基準，未修改欄位沿用其他裝置的新值；同一欄位衝突以最後成功提交為準。已在另一裝置刪除的個案，不會由過期表單重新建立。
寫入失敗保留草稿，明示未確認；未儲存草稿離開頁面會要求瀏覽器提示。輸入只以textContent顯示。依使用者決定，舊本機個案不自動上傳。

驗證：cases.test.cjs測試資料與搜尋；cloud-sync.test.cjs測試合併、分片、刪除、失敗與帳號隔離。隔離瀏覽器及模擬Firestore以虛構資料測試兩裝置CRUD、同病人不同欄位合併、拒絕儲存草稿保留、登出與1440／390／320版面。
真實Firebase SDK未登入啟動及鎖定個案介面已檢查；正式擁有者登入寫入與第二裝置讀回仍須由使用者帳號完成最後驗證。測試資料與畫面不發布。
